# A2A 1.0 gateway contract (#71)

This module is an offline, provider-neutral boundary for a bounded remote executor. It has no network implementation or scheduler/runtime embedding. The live bridges are owned by #78. It never grants root or parent authority, edits a TaskGraph, imports a reviewer, or marks a Herdr task complete.

## Protocol assumptions

The current released specification patch is v1.0.1; the negotiated Major.Minor value is `1.0`. Patch versions do not affect compatibility. Every transport method receives `A2A-Version: 1.0`. A live transport must put that header on each request and convey the selected interface tenant in the binding-specific request service parameters. This contract permits the canonical JSONRPC, GRPC, and HTTP+JSON interface bindings. A2A v1.0.1 requires each production `AgentInterface.url`, including GRPC, to be an absolute HTTPS URL. Optional interface `tenant` values are bounded opaque strings and are echoed exactly in service parameters. It does not choose or call a transport.

Primary sources: [A2A v1.0.1 specification](https://a2a-protocol.org/v1.0.1/specification/) and [normative a2a.proto data model](https://github.com/a2aproject/A2A/blob/main/specification/a2a.proto).

Cards are discovered at `https://host/.well-known/agent-card.json`. A card is metadata, never authorization. `supportedInterfaces` lists URL, `protocolBinding`, optional tenant, and `protocolVersion`, with the first preferred. The parser accepts a bounded subset of known card fields and rejects unknown card fields, oversized content, embedded secret-like values, non-HTTPS interface URLs, incompatible versions, empty required `skills`, and any server extension marked `required=true` because #71 advertises no extension support. A local `Admission` must match both the exact card digest and one exact interface digest. Discovery alone creates no registry candidate. The registration helper returns a typed executor, unknown-health runtime snapshot, and provenance only after admission; callers must explicitly insert these into a separately authorized registry snapshot. Its IDs and tools come from local policy, not the card.

## Economic and delivery boundary

`Identity` holds the exact Herdr parent and child agent IDs, local task ID, run token, fencing token, and idempotency key. The deterministic A2A `messageId` hashes all six values. Remote context, task, or session IDs are observations and cannot reset that identity, fence, or budget. Local `Admission` pins one host-selected `binding_root` for per-attempt state, but economic uniqueness is global to the Herdr identity: before transport, `BindingStore` creates a permanent fsync-durable claim named by the deterministic `messageId` under the fixed host-owned `/var/lib/herdr/a2a-economic-claims` authority root. Changing either the binding filename or the admitted binding root therefore cannot produce a second economic send for the same identity. A crash after the claim but before a usable remote binding remains fail-closed and requires external reconciliation. Binding directories and the claim root are opened component-by-component with `O_NOFOLLOW`, so an ancestor symlink cannot redirect the ledger. A2A SendMessage only **may** deduplicate `messageId`; blind resend could duplicate economic work.

A bound remote task can be polled with idempotent GetTask. GetTask and CancelTask responses are parsed as the protocol's bare `Task` objects (while bounded normalized wrappers remain accepted for transport adapters). Cancel intent is persisted before CancelTask, and `retry_cancel` can repeat the idempotent cancel after restart. All operations require an exact local identity and card/interface admission match; task and context observations must match the stored remote binding. A stale fence or mismatched remote task/context is rejected. This file is an observation/binding record, not a scheduler or economic queue. Candidate history is bounded. Before GetTask or CancelTask, the gateway reserves enough ledger capacity for the largest valid response (one status message plus the bounded artifact set); when that capacity is exhausted it fails **before** the remote call, so a valid late result is never observed and then discarded because persistence overflowed.

SendMessage can return a Task or a Message. A server Message without taskId is direct and not pollable; a server Message carrying taskId binds that exact remote task/context and becomes pollable without creating a new Herdr economic identity. Task contextId is optional; once the first response binds its exact value (including absence), later observations may not silently change it. A TaskStatus `message` is preserved as a result candidate as well, so requesting `historyLength=0` cannot discard the current agent answer. Remote task/context/message/artifact identifiers are bounded opaque UTF-8 strings but reject Unicode control/format/surrogate characters. TASK_STATE_UNSPECIFIED is accepted only as a non-terminal observation. Terminal states are COMPLETED, FAILED, CANCELED, and REJECTED; INPUT_REQUIRED and AUTH_REQUIRED are interrupted states. Part.data accepts any bounded JSON value (object, array, string, number, boolean, or null), while raw accepts conformant ProtoJSON bytes encodings: standard or URL-safe base64, with or without padding. The parser bounds messages, tasks, parts, and artifacts. Artifacts and messages become immutable canonical-byte result/evidence candidates with SHA-256 digests and exact local identity. A remote COMPLETED state is solely an execution observation; shared #85 acceptance remains required before any Herdr completion or commit. The gateway does not implement a second evidence reviewer.

Remote artifact text can decode to `ChildProposal` data. A caller may pass that value to `DynamicChildScheduler.evaluate_child_proposal` or consumer validation. The gateway never calls `spawn_child`, mutates a graph, or treats remote proposal fields as authority. Local parent role, tools, and permissions are supplied by the caller and cannot be overwritten by the artifact. The existing scheduler and consumer own child admission.
