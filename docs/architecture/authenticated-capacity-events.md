## Host attestation

The v1 receipt bound host, scope, time and a report digest. It established that root published bytes, while permitting an issuer to copy publisher-supplied capacity and policy without measuring either. The reader also accepted receipts up to the general 15-minute observation limit. v1 did not identify the measured filesystem or method, constrain the receipt to the installed threshold, or provide an issuer with a protected publication path.

The one-shot attestor checks effective UID 0 and the expected kernel hostname, reads the watcher through the existing protected descriptor reader, measures the fixed root filesystem through `fstatvfs`, then rereads the watcher. The exact capacity counters must match the independent measurement and the installed floor plus guard (9,797,894,144 bytes). The watcher JSON must satisfy its exact schema and derived-counter checks. Report bytes must remain equal across both reads. Source data outside the 30-second attestation window, future source data and backward clock movement during issuance fail closed. The attestor writes a deterministic v2 receipt through the existing atomic writer at `/run/herdr/capacity-exporter/receipt.json`, with protected root-owned ancestry and a root-owned, single-link, read-only final file. Its reader binds the same report bytes, host, scope, event time, filesystem, method and counters. It rejects v1 and caps current trust at 30 seconds, including on replay. Old or otherwise unmatched inputs yield no TaskProposal.

An authorized operator must provision the already-reserved directory through existing host policy and run the installed module with a trusted interpreter, trusted package path, native host mount and UTS namespaces, a trustworthy host clock, and fixed host-selected server/consumer/project arguments. Root and those host inputs are the trust boundary. A namespace-local hostname is insufficient to establish host provenance in a container. The checkout, watcher report and operator-supplied environment are unsuitable as privileged code sources. No unit, timer, directory, permissions, credentials or production policy are installed here. A privileged invocation from a writable checkout is outside this contract.

The attestor corroborates a recent sample. A capacity change even by one block between readings may prevent issuance. Availability needs a separately approved invocation near report publication. Concurrent publications or report replacement after sampling can yield a mismatched pair, which the reader blocks. Root clock rollback between invocations is outside this contract. Receipts live under volatile `/run`; operator-managed archival evidence has a separate protected `EvidenceStore` trust boundary. Any v1 records must be preserved as historical evidence outside an active v2 replay set.

`canary` is a read-only observation. `record_host_observation` and `replay_recorded` are explicit offline entry points. Their caller must supply a host-protected evidence directory outside worker-writable roots. Replay fails closed beyond 1,024 capacity records or 8,192 directory entries. A reviewed retention and archival policy is required before continuous operation.
