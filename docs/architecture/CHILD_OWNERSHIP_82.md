# Child ownership and finite write mounts (#82)

Each new mutating child declares ownership in the granted delegation tool or socket request. The closed contract contains write_scope, decision_scope, hard_dependencies, shared_dependencies, integration_owner and handoff_ref. The integration owner is the authenticated parent task. A repeated delegation key must preserve this contract, objective, prompt and worktree identity.

A file/directory scope uses a relative worktree path. A resource scope reserves a logical external resource; it does not itself authorize a tool, network request or filesystem mount. Decision scopes reserve versioned contract keys. Shared dependencies name a host-frozen version, content digest and integration owner. New decision versions invalidate dependent reservations; they do not mint an attempt, reset a counter or expand a grant.

The TaskGraph remains the execution authority. OwnershipRegistry is a host resource reservation store shared across parent ledgers. It is not a second task queue. The registry commits a reservation before the existing scheduler creates its claim, then binds the exact consumer, agent, parent agent/task, task, run and fencing token. Cross-parent conflicts, unknown writers and stale contracts block before an economic invocation. Hard dependencies also require accepted TaskGraph completion and physical cleanup.

The host bridge derives the parent identity from the accepted launch grant, not from a locally generated external-parent fence. It scans bounded protected canonical child ledgers while holding the global registry lock. Legacy mutating children with missing ownership remain quarantined, including pending claims. Neither submitted DONE, observed pane disappearance nor a cleanup flag retires such a legacy writer. Corrupt, missing-required, replaced, symlinked, hardlinked or writable ledgers deny new writes. Known claims must match the exact registered identity and scope. Read-only tools can retain legacy request compatibility.

For an owned launch, the worktree is read-only. The host opens each declared existing file/directory under held no-follow directory descriptors and verifies UID, mode, kind, inode and ancestor bindings. Control paths such as .git and .herdr are rejected. The sandbox receives finite bind-fd write mounts, and the host narrows the signed write/patch tool rules to those same paths. A directory claim permits creation within that directory; runtime file claims require an existing target. Automatic file creation is not enabled without a prepared WorkPlan that can account for it.

Before launch, the host durably records the exact owned inode observations against the claim and worktree identity. The signed sandbox attestation includes the ownership digest and mount observations. Cold replay validates their identity, scope and immutability; retained-process verification checks the authenticated policy proof and actual kernel mounts. Unexpected mounts under the worktree, stacked mounts and changed owned inodes deny. Closing host pin descriptors after seal leaves the kernel bind mounts intact and does not release ownership.

Resource release and frozen-contract publication are host-only operations requiring a host verifier. The granted tool and socket protocol expose neither operation. The production bridge releases terminal owned reservations only when HostOwnershipRelease verifies protected cleanup and actual namespace quiescence. Frozen-contract publication and semantic acceptance are separate host ports composed with #85; model prose cannot release a writer or publish an accepted shared contract.

The read-only snapshot reports ownership digest, finite write/decision scopes, shared dependencies, integration owner, handoff reference, registry reservation and observed mount identities. Missing metadata remains unknown. These fields are observation and provenance; they do not grant authority.

Validation includes canonical-ledger recovery and tamper boundaries, actual SDK handler/schema transport, cross-process registry conflicts, logical grant narrowing and actual Linux parent/child signed grants. Kernel tests permit writing the owned file, reject a foreign sibling and reject an extra physical bind beneath the read-only worktree. Physical bootstrap and installed SDK probes are run separately, without a provider invocation or production configuration change.

## Legacy admission lifetime and recovery

A directory snapshot cannot prevent a pre-upgrade bridge from making a later claim. New host entrypoints retain a shared flock on the original worker.lock inode; old workers use its exclusive flock. New coordinators use worker.loop.lock to serialize their own loop. A bridge holds the shared fence from reservation through physical namespace launch. A host-only custodian holds a separate non-inherited shared FD throughout every new root/child namespace. PR_SET_PDEATHSIG plus bubblewrap --die-with-parent kill that namespace when custody ends; model processes receive no lock FD.

Canonical running, blocked and pending parents are also checked before new writer admission. A live pre-upgrade parent without the exact host-owned epoch/run/fence binding remains quarantined even before it has created a child ledger. Pending uncertain-delivery attempts are included. Only a newly allocated host attempt receives an epoch marker before fsynced delivery; cold reconciliation never upgrades a legacy attempt. Existing pre-opened legacy FDs therefore cannot acquire their exclusive admission lock while a new writer exists.

Owned pre-delivery recovery reopens the protected logical worktree through no-follow ancestor FDs, verifies its exact recorded device/inode, and retains that pin through cleanup. A replaced inode or symlink denies cleanup; this recovery neither mints a grant nor repeats prompt delivery. Runtime write/create/delete/move operations reject every relative .git/.herdr/.herdr-* component before any mkdir or file effect, including entries introduced after bootstrap.

## Host release and bounded active history

The bridge and protected recovery wire HostOwnershipRelease. It reads the exact canonical parent/child ledger, terminal identity and cleanup truth. A mutating child also requires the host-captured lifetime of its verified PID-namespace init. Its PID/start-tick binding must match the sandbox attestation. An init still alive cannot release ownership or open the accepted-result barrier; namespace exit kills its descendants. Old records without this proof retain quarantine. Read-only tools cannot acquire write authority through release.

Released reservations are compacted in bounded batches into immutable per-key private receipts. A fully written/fsynced receipt is published before the active index removes the row. Restart can reconstruct the same historical claim, but reserve/bind/delivery queries reject its released key. Result queries still validate current shared contracts. Archive lookup is bounded and direct; the active registry does not accumulate every completed child. Frozen-contract publication remains a separate host-verifier operation.

## Typed handoff

Every new protected child publication and bridge response contains a versioned bounded HandoffEnvelope. It binds full child identity, child specification digest, original result/evidence references, roles and ownership. Unknown Git base/semantic acceptance remain explicit UNKNOWN; publication does not manufacture accepted verification. Historical publications are preserved rather than relabelled as newly verified.

A candidate may submit bounded handoff_details for assumptions, unknowns, contradictions, pending criteria, blockers, next_action and explicitly unowned/out-of-scope work. Contradictions produce CONFLICT; pending acceptance produces PARTIAL. Neither can publish completed. Current binding checks reject changed task/run/artifact/scope/base or stale shared contracts. The envelope contains data references and creates no grant, additional execution queue, scope expansion or automatic economic continuation. #85 supplies acceptance evidence; #86 supplies frozen base/scope plan authority.
